**Create useReconnect.ts** per D-10, D-11, D-12:

```typescript
interface UseReconnectOptions {
  reconnectFn: () => void;          // useMudSocket's reconnect()
  onReconnecting: (attempt: number) => void;  // UI update callback
  onGaveUp: () => void;             // max attempts reached callback
}

interface UseReconnectReturn {
  scheduleReconnect: () => void;    // call this from onClose
  cancelReconnect: () => void;      // call on intentional disconnect
  resetAttempts: () => void;        // call on successful onOpen
  attempt: number;                  // current attempt count
  isReconnecting: boolean;
}

export function useReconnect(options: UseReconnectOptions): UseReconnectReturn
```

Exponential backoff parameters (Claude's discretion per CONTEXT.md):
```typescript
const BACKOFF_BASE = 500;       // 500ms initial delay (matches current first retry)
const BACKOFF_MAX = 30_000;     // 30 second cap
const BACKOFF_MULTIPLIER = 2;   // double each attempt: 500, 1000, 2000, 4000, 8000, 16000, 30000
const JITTER_RANGE = 0.5;       // +/- 50% randomization
const MAX_ATTEMPTS = 15;        // give up after ~2 minutes total
```

Backoff calculation:
```typescript
function getBackoffDelay(attempt: number): number {
  const exponential = Math.min(BACKOFF_BASE * Math.pow(BACKOFF_MULTIPLIER, attempt), BACKOFF_MAX);
  const jitter = exponential * JITTER_RANGE * (Math.random() * 2 - 1);
  return Math.max(0, Math.round(exponential + jitter));
}
```

State management:
- `attemptRef = useRef(0)` for attempt counter (ref, not state, to avoid stale closures in setTimeout)
- `timerRef = useRef<number | null>(null)` for the setTimeout ID
- `isReconnecting` state boolean for UI

`scheduleReconnect()`:
1. Increment `attemptRef.current`
2. If attempt > MAX_ATTEMPTS, call `onGaveUp()`, set `isReconnecting = false`, return
3. Compute delay via `getBackoffDelay(attemptRef.current - 1)`
4. Call `onReconnecting(attemptRef.current)`
5. Set timer: `timerRef.current = window.setTimeout(() => options.reconnectFn(), delay)`
6. Set `isReconnecting = true`

`cancelReconnect()`: Clear timer, reset attempt counter, set `isReconnecting = false`

`resetAttempts()`: Clear timer, reset attempt counter to 0, set `isReconnecting = false`. Call this from `onOpen` callback to reset after successful connection.

Cleanup: `useEffect` return clears `timerRef` on unmount.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Server (WebSocket reconnect) | Reconnection uses resume token; untrusted client cannot fabricate sessions |
| Service worker -> Cache API | Cached assets served from local storage; HTTPS ensures integrity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Spoofing | WebSocket reconnection | mitigate | Server validates resume token on reconnect; client cannot fabricate sessions. Existing `resumeTokenRef` pattern preserved (verified in App.tsx) |
| T-03-07 | Denial of Service | Reconnection storm | mitigate | Exponential backoff with jitter (D-12): 500ms base, 2x multiplier, 30s cap, 50% jitter randomization, 15 max attempts. Prevents thundering herd on server recovery |
| T-03-08 | Tampering | Service worker cache poisoning | mitigate | App served over HTTPS only; Vite produces content-hashed filenames for JS/CSS bundles; versioned cache name (ambonmud-v2) forces cache refresh on deployment. Old caches deleted on activation |
| T-03-09 | Information Disclosure | Cached assets in Cache API | accept | Only static assets cached (HTML, JS, CSS, icons). No sensitive game state cached client-side. iOS may evict after 7 days (Research Pitfall 6) -- acceptable since all state is server-authoritative |

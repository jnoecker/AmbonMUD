## Layout Contract

This is the primary visual contract for Phase 2. It defines the structural zones, breakpoints, and responsive behavior.

### Viewport Zones

```
+-------------------------------------------+
|  env(safe-area-inset-top)  padding        |
+-------------------------------------------+
|                                           |
|              CANVAS ZONE                  |
|     (grid-area: canvas)                   |
|                                           |
+-------------------------------------------+
|  HUD SLOT  (grid-area: hud)  60px fixed   |
+-------------------------------------------+
|                                           |
|          INTERACTION ZONE                 |
|     (grid-area: interaction)              |
|     env(safe-area-inset-bottom) padding   |
+-------------------------------------------+
```

### Breakpoints

| Name | Range | Canvas Height | HUD Slot | Interaction Zone | Layout Mode |
|------|-------|---------------|----------|------------------|-------------|
| Mobile | < 768px | `clamp(60%, 65vh, 75%)` | 60px fixed | Remaining (`1fr`) | Stacked zones |
| Tablet | 768px - 1023px | `clamp(55%, 60vh, 70%)` | 60px fixed | Remaining (`1fr`) | Stacked zones |
| Desktop | >= 1024px | `1fr` (100% viewport) | Floating overlay | Floating overlay | Full-canvas with overlays |

**Source:** CONTEXT.md D-01, D-02, D-03, D-05; RESEARCH.md Architecture Pattern 1.

### CSS Grid Specification

```css
/* Mobile-first (< 768px) */
.layout-shell {
  display: grid;
  grid-template-rows: clamp(60%, 65vh, 75%) 60px 1fr;
  grid-template-areas:
    "canvas"
    "hud"
    "interaction";
  height: 100dvh;
  overflow: hidden;
  padding-top: env(safe-area-inset-top, 0px);
  padding-left: env(safe-area-inset-left, 0px);
  padding-right: env(safe-area-inset-right, 0px);
}

/* Tablet (768px - 1023px) */
@media (min-width: 768px) {
  .layout-shell {
    grid-template-rows: clamp(55%, 60vh, 70%) 60px 1fr;
  }
}

/* Desktop (>= 1024px) */
@media (min-width: 1024px) {
  .layout-shell {
    grid-template-rows: 1fr;
    grid-template-areas: "canvas";
  }
}
```

**Source:** CONTEXT.md D-06 (Claude's discretion); RESEARCH.md recommends Grid over Flexbox for cleaner breakpoint transitions.

### Safe Area Insets

| Edge | Applied To | Fallback |
|------|-----------|----------|
| Top | `.layout-shell` padding-top | 0px |
| Left | `.layout-shell` padding-left | 0px |
| Right | `.layout-shell` padding-right | 0px |
| Bottom | `.layout-shell__interaction` padding-bottom | 0px |

**Prerequisite:** `<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />` must be added to `web-v3/index.html` (currently missing `viewport-fit=cover`).

**Source:** RESEARCH.md Pitfall 1, Code Examples section.

### Desktop Overlay Behavior

On desktop (>= 1024px), the HUD and interaction zone do not exist as grid rows. Instead:
- Existing panels render as floating overlays via `position: absolute` over the canvas
- Overlay container uses `pointer-events: none`; visible panel children use `pointer-events: auto`
- Canvas receives all click/tap events when no panel is open

**Source:** CONTEXT.md D-03; RESEARCH.md Pitfall 6.

### Panel Repositioning (Transitional)

| Component | Mobile Behavior | Desktop Behavior |
|-----------|----------------|-----------------|
| Action bar | Moves into InteractionZone | Remains as floating overlay |
| Top banner | Shrinks into HUD slot | Remains as floating overlay |
| Terminal/combat log | Hidden entirely | Unchanged |
| Existing panels/popouts | Rendered in InteractionZone | Floating overlays |

**Source:** CONTEXT.md D-09, D-10. Transitional appearance is acceptable; everything must remain functional.

## Canvas Safety Contract

### DPR Capping

| Device Class | Max Resolution | Detection |
|-------------|---------------|-----------|
| Mobile (< 1024px viewport) | 2x device pixel ratio | `Math.min(window.devicePixelRatio \|\| 1, 2)` |
| Desktop (>= 1024px viewport) | Native (uncapped) | `window.devicePixelRatio \|\| 1` |

Applied in `PixiCanvas.tsx` during `app.init()` via the `resolution` parameter.

**Source:** CONTEXT.md D-08; REQUIREMENTS.md CANVAS-03.

### Texture Garbage Collection

| Setting | Mobile Value | Desktop Value | API |
|---------|-------------|---------------|-----|
| `gcActive` | `true` | `true` | `app.init()` option |
| `gcMaxUnusedTime` | 5000ms | 60000ms | `app.init()` option |
| `gcFrequency` | 5000ms | 30000ms | `app.init()` option |

**Source:** CONTEXT.md D-07; REQUIREMENTS.md CANVAS-02; RESEARCH.md verified PixiJS 8.16 GCSystem API.

### VRAM Budget Manager

| Property | Mobile | Desktop |
|----------|--------|---------|
| Budget cap | 64 MB | 256 MB |
| Warning threshold | 80% (51.2 MB) | 80% (204.8 MB) |
| Estimation multiplier | 1.5x raw calculation | 1.5x raw calculation |
| Over-budget fallback | Drop to 1x resolution + disable parallax | Log warning only |

**Texture lifecycle:**
- Track texture allocation via `width * height * 4 * 1.5` (conservative estimate)
- On scene transitions, call `texture.source.unload()` on all textures of the exiting scene
- Use `Assets.unload(key)` for full cache removal when budget is critically exceeded

**Source:** CONTEXT.md D-07; RESEARCH.md Pattern 3, Pitfall 5.

## Interaction Contract

### Touch/Pointer Behavior

| Zone | Touch Behavior | Notes |
|------|---------------|-------|
| Canvas Zone | Pass-through to PixiJS `pointertap` events | Existing canvas interaction preserved |
| HUD Slot | Non-interactive in this phase | HP/mana/XP bars are display-only until Phase 3 |
| Interaction Zone | Existing panel interactions preserved | Action bar buttons, popout triggers remain functional |
| Desktop overlays | `pointer-events: none` on container, `auto` on visible panels | Prevents overlay from blocking canvas taps |

### Resize Behavior

| Trigger | Response | Notes |
|---------|----------|-------|
| Viewport resize (orientation change) | Grid reflows; canvas ResizeObserver fires | Debounced -- PixiJS handles via existing `resizeTo: container` |
| iOS Safari address bar animation | `100dvh` tracks dynamic viewport | No JS intervention needed |
| Window resize (desktop) | Canvas fills available space; overlays reposition | Existing `ResizeObserver` in `PixiCanvas.tsx` handles this |

**Anti-pattern:** Do not use `dvh` on nested elements. Only the outermost `.layout-shell` uses `100dvh`. Inner zones use Grid row sizing.

**Source:** RESEARCH.md Anti-Patterns, Pitfall 3.

## Breakpoint Migration Strategy

The existing codebase uses breakpoints at 960px, 480px, and 640px. This phase introduces new breakpoints at 768px and 1024px for the LayoutShell. Both sets coexist temporarily.

| Old Breakpoint | New Breakpoint | Migration |
|---------------|---------------|-----------|
| `max-width: 959px` | `max-width: 767px` (mobile) | Migrate incrementally within this phase |
| `min-width: 960px` | `min-width: 1024px` (desktop) | Migrate incrementally within this phase |
| `max-width: 480px` | Removed (absorbed into mobile < 768px) | Migrate incrementally within this phase |
| `max-width: 640px` | Removed (absorbed into mobile < 768px) | Migrate incrementally within this phase |
| `min-width: 960px and max-width: 1120px` | `min-width: 768px and max-width: 1023px` (tablet) | Migrate incrementally within this phase |

**Rule:** New LayoutShell classes use new breakpoints exclusively. Existing panel classes may retain old breakpoints temporarily if migration creates risk, but the goal is to migrate all rules by end of phase.

**Source:** CONTEXT.md D-05; RESEARCH.md Pitfall 4.

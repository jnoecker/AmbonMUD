**1. Refactor `web-v3/src/gmcp/applyGmcpPackage.ts` (D-05, D-06):**

Replace the `GmcpContext` interface (80+ individual setters) with a `GmcpDispatchMap` interface:

```typescript
import type { Dispatch } from "react";
import type { CoreAction } from "../state/CoreContext";
import type { CombatAction } from "../state/CombatContext";
import type { InventoryAction } from "../state/InventoryContext";
import type { SocialAction } from "../state/SocialContext";
import type { WorldAction } from "../state/WorldContext";
import type { QuestAction } from "../state/QuestContext";
import type { UIAction } from "../state/UIContext";

export interface GmcpDispatchMap {
  core: Dispatch<CoreAction>;
  combat: Dispatch<CombatAction>;
  inventory: Dispatch<InventoryAction>;
  social: Dispatch<SocialAction>;
  world: Dispatch<WorldAction>;
  quest: Dispatch<QuestAction>;
  ui: Dispatch<UIAction>;
  // Non-dispatch utilities that remain unchanged:
  updateMap: (roomId: string, exits: Record<string, string>, title: string, image: string | null, mapX: number, mapY: number, housing?: boolean) => void;
  loadZoneMap: (zone: string, rooms: Array<{ id: string; x: number; y: number; exits: Record<string, string> }>) => void;
  sendGmcp: (pkg: string, payload: unknown) => boolean;
  pushCombatEvent: (event: CombatEventData) => void;
  pushGainEvent: (event: GainEvent) => void;
  resumeTokenRef: { current: string | null };
  pendingAuthCharRef: { current: string | null };
  failedAuthCharRef: { current: string | null };
}
```

Change the function signature from `applyGmcpPackage(pkg, data, ctx: GmcpContext)` to `applyGmcpPackage(pkg, data, ctx: GmcpDispatchMap)`.

Then refactor EVERY switch case to use dispatch actions instead of individual setters. Follow the GMCP Package to Context Mapping table from RESEARCH.md. Examples of the transformation:

- `ctx.setVitals(parsedVitals)` becomes `ctx.core({ type: "SET_VITALS", vitals: parsedVitals })`
- `ctx.setRoom(parsedRoom)` becomes `ctx.world({ type: "SET_ROOM", room: parsedRoom })`
- `ctx.setRoomFeatures([])` becomes `ctx.world({ type: "SET_ROOM_FEATURES", roomFeatures: [] })`
- `ctx.setContainerContents(null)` becomes `ctx.ui({ type: "SET_CONTAINER_CONTENTS", containerContents: null })`
- `ctx.setChatByChannel(...)` complex updater becomes `ctx.social({ type: "PUSH_CHAT_MESSAGE", channel, message })` -- the reducer handles trimming
- `ctx.setCombatTarget(parsed)` becomes `ctx.combat({ type: "SET_COMBAT_TARGET", combatTarget: parsed })`
- `ctx.pushCombatEvent(event)` stays as `ctx.pushCombatEvent(event)` (imperative, not state)
- `ctx.pushGainEvent(event)` stays as `ctx.pushGainEvent(event)` (imperative, not state)
- `ctx.pushFriendNotification(n)` becomes `ctx.ui({ type: "PUSH_FRIEND_NOTIFICATION", notification: n })`
- `ctx.pushQuestNotification(n)` becomes `ctx.quest({ type: "PUSH_QUEST_NOTIFICATION", notification: n })`
- `ctx.pushUiFeedback(feedback)` becomes `ctx.combat({ type: "PUSH_COMBAT_LOG_MESSAGE", message: { id: Date.now(), text: feedback.message, style: ..., receivedAt: Date.now() } })` (examine current pushUiFeedback to replicate exact behavior)
- `ctx.pushBroadcast(sender, msg)` becomes `ctx.ui({ type: "SET_BROADCAST", broadcast: { sender, message: msg } })`
- `ctx.pushCraftingResult(result)` becomes a combat log message dispatch (examine current pushCraftingResult in App.tsx to replicate exact format)
- `ctx.pushMailNotification(n)` becomes a combat log message dispatch (examine current implementation)
- Cross-context dispatches: `ctx.setShop(value)` that also clears popout becomes TWO dispatches: `ctx.inventory({ type: "SET_SHOP", shop: value })` AND if value is null: `ctx.ui({ type: "SET_ACTIVE_POPOUT", activePopout: null })` (but only if current popout is "shop" -- since reducer can't check this, use a conditional in the GMCP handler)

**CRITICAL for cross-context dispatches:** Read the GMCP mapping table in RESEARCH.md. These cases dispatch to multiple contexts:
- `Room.Info` -> world (room) + ui (clear container)
- `Shop.Close` -> inventory (clear shop) + ui (close popout)
- `Friends.*` -> social (friends list) + ui (friend notifications)
- `UI.Feedback` -> combat (push combat log message)

**For complex push/notification patterns** (pushCombatEvent, pushGainEvent, pushCraftingResult, pushMailNotification, pushUiFeedback): Read the current useCallback implementations in App.tsx (around lines 292-371) to understand exactly what each does. Some of these push to canvasEvents AND to combat log. The canvasEvents pushes stay as imperative callbacks on the dispatch map. The combat log pushes become PUSH_COMBAT_LOG_MESSAGE dispatch actions.

If any GMCP case uses a `setState(prev => ...)` updater function pattern (functional updates), the corresponding reducer action must handle the same logic. Migrate every panel/component from props to useContext consumption. This is a mechanical transformation with a consistent pattern:

**Pattern for every component:**
1. Read the current component file to identify its props interface
2. For each prop that maps to context state (e.g., `vitals`, `inventory`, `combatTarget`):
   a. Add the appropriate `use{Domain}State()` import and call
   b. Destructure the needed fields from the context state
   c. Remove that prop from the interface
3. For props that are CALLBACKS (e.g., `onCommand`, `onWearItem`, `onDropItem`):
   a. These may STAY as props if they involve imperative actions (sendCommand) not in context
   b. OR they can use dispatch if they only update state
   c. Decision: Read AppShell to see what it passes. Callbacks involving `sendCommand` or `focusComposer` should stay as props. Pure state mutations should use dispatch.
4. For DERIVED props (e.g., `hasCharacterProfile`, `xpText`, `visibleEffects`, `canOpenEquipment`):
   a. Move the derivation INTO the component (compute from context state)
   b. Use `useMemo` if the derivation is expensive
5. Remove the old Props interface type if it becomes empty, or keep a minimal interface for remaining callback/ref props
6. Update AppShell's JSX to stop passing the removed props
